## §1 选型的第一性标准（可直接采纳）

> **原话**："**简单或者不急的任务呢，要考虑性价比；紧急的任务那就要考虑速度跟完成质量。**"

| 任务性质 | 优先项 | 本技能的对应做法 |
|---|---|---|
| **简单 / 不急** | **性价比** | 小样、构图探索 → **低步数快速模型**（Hyper-SDXL / LCM，1–2 步，5 秒一版）；本地跑，零成本 |
| **复杂 / 正式** | **质量** | 定稿 → **Flux.1-dev fp8**（24 步 + 超分），本机 5080 |
| **紧急 / 关键** | **速度 + 质量并行** | 多模型/多参数并行出，再挑 —— 本机对应**一次出 N 张 → `vqc.py` 量化排序选赢家** |

> **一条现实提醒（作者原话）**："普通人哪有时间、技术能力跟资金实力把每家大模型的每个版本都研究的非常清楚。"
> → 本技能的原则不变：**别研究，先按"急不急"分档，用起来再调。**

## §2 多模型路由与协作（v18 · 工具名待核实）

### 作者介绍的机制

| 机制 | 说明 |
|---|---|
| **智能模型融合路由** | 简单问题走**轻量模型**（快、便宜）；复杂任务上**旗舰模型**；**关键任务几个模型并行跑完，然后把输出揉成一份给你** |
| **聚合 API** | 一个 API 接进去，DeepSeek / GLM / Kimi / 千问等主流模型都在里面，**用量统一统计**，不用每家分开买 |

> **⚠ 名称待核实（转写出现三种写法）**：开源项目被念成 **"OpenSora" / "OpenSqila" / "OpenSquirrel"**；
> 聚合 API 被念成 **"TokenRhythm"**。**三个名字互相矛盾 → 不要按名字检索**，等看到画面再确认。
> 视频称该项目在 GitHub 开源，7 月 31 日有最新 release —— **未核实**。

### 一次实测案例（作者自述，非本机验证）

新建项目"**AI 热点选题雷达**"，写一份任务说明书发出后：

```
① 进入 AI 模型路由 → 判定使用 GLM 5.2 作为主模型
② 任务被拆成 6 个阶段
③ 搜索网页 → 判定信息足够
④ 进入分析阶段 → 主模型选出 5 个候选话题
⑤ 主模型给子 agent 下达任务 → 输出 top3 编号 + 排名 + 推荐理由 + 主要风险
⑥ 三个子智能体用不同模型完成评审 → 选出最终前三
⑦ 进入网页开发 → 生成可直接使用的本地网页
```

**成本**（作者自述）：整体**不到 10 分钟**，总花费**不到 2.1 美元**；token 用量 GLM 最多、Kimi 其次、DeepSeek 最少。

### 抽象出两条可跨域复用的协作范式

1. **"主模型拆分 + 子 agent 并行 + 评审收敛"**
   → 本机对应：**一次出 N 张候选 → `vqc.py pick` 量化排序 → 只修该修的那一项**（`vqc/vfix` 闭环）。
   **并行出稿 + 机器排序**就是本地版的"多智能体评审"。
2. **子 agent 之间要用不同模型/不同视角**（视频里"三个子智能体使用不同的模型完成评审"）
   → 本机对应：**12 维审稿的多个维度必须分开判**，不要一个"总分"盖掉结构错误
   （跨库引用 `田伟平总监审核标准` §3）。

## §3 AI 建站 / 网页交付（v20 · 工具名待核实）

> 作者原话结论：**"以前一个团队干一周的效果，现在一天给它搞定。"**
> **"AI 并不会替代设计师，但它会让设计回归设计效果的本身。"**

### 三步流程

| 步 | 操作 | 关键点 |
|---|---|---|
| **1 · 给素材** | 主页里放**产品图片 + 告诉它是什么产品**；或**图片 + AI 写的提示词**；或直接打一段话 | **"如果想要更精准的话，是可以把竞品官网，或者是品牌的设计稿直接放进去。"** |
| **2 · 改** | 预览上方有**箭头**，**想改哪里直接点选对应模块** | 例：点图片 → "给我替换成我上传的视频"；点图标 → 生成其他样式 |
| **3 · 输出** | 直接输出**可上线的网站**；**可连接 GitHub**；支持**多端验收**（桌面端看大屏 / 手机端看 Web） | 全程自然语言，不写代码 |

> 能力自述：复刻网站排版结构、生成**带视差滚动的 Hero Section**、添加 **loading 交互动效**。
> 新版**国际版与中国版同时内测上线**。
> **⚠ 工具名待核实**：口播被转写成 **"吹solo" / "Tresolo"**，画面未拍到站名（`f_004` 只拍到成品站与右侧"工具/保存/分享/设置"侧栏）。

### 三条可采纳的点（与工具本身无关）

1. **"放竞品官网 / 品牌设计稿" = 给风格干料**。
   这印证了本技能第零步的使用技巧"**可加示例锚定风格**" —— **参考物的颗粒度越"干"（真实成品/品牌稿），结果越准**；
   放一句"想要高级一点"反而最差。
2. **"它会问你的需求是什么，并且给你选择"** —— 这已经是**行业共识动作**。
   本技能第零步的"**让 AI 先问三个问题**"（v15）与此**同源**，可放心当作标准流程。
3. **"想改哪里，直接选择对应的模块"** —— **第三次出现"指哪改哪"**
   （另两次见 `digital-human-video-pipeline.md` §4）。
   → **已升格为本技能铁律：可定位的修改，永远优于可描述的修改。**

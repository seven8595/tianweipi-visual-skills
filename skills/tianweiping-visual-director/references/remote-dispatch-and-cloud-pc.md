## 0. 为什么这条要写进视觉技能

本技能的核心矛盾一直是：**重活必须在 RTX 5080 上跑，但人不可能一直坐在电脑前。**

这条视频给的正是解法：**人在外面 → 手机派单 → 本机干活 → 回来看结果。**
与既定工作模型完全一致：**PC 做 GPU 推理，手机做远程控制终端。**

对应到本技能的「自主执行模式」：原来那 3 个必须用户拍板的节点（风格方向 / 最终选稿 / 对外发布），**本来就需要你参与，但不必发生在电脑前**。

## 1. 两种模式（先分清，选错白等）

| | **本地电脑模式** | **云电脑模式** |
|---|---|---|
| 跑在哪 | **你自己的电脑** | 豆包提供的云端机器 |
| 前置条件 | **电脑必须开着** | **不需要家里电脑开机** |
| 能否读本机文件 | ✅ 能 | ❌ **读不到关机电脑里的文件** |
| 适合什么 | **本机 ComfyUI / Flux 出图、跑本地脚本、动本机文件** | 手机上传资料的处理、**不依赖本地文件**的任务（调研、文案、排期） |
| 对本技能的意义 | **唯一能出图的那条路** | 只能跑辅助任务 |

> **一句话结论**：**出图只能走「本地电脑模式」。**
> 云电脑上**没有你的 5080、没有 ComfyUI、没有 flux1-dev 与 LoRA** —— 不要指望它在云端替你出图。

## 2. 本地电脑模式：连接步骤（照视频）

1. 电脑打开豆包 → 选择 **【豆包工作模式】**
2. 登录你的账号
3. 按页面提示 **【连接本地电脑】**
4. **手机登录同一个豆包账号**
5. 连接成功后，直接在手机上告诉它：**要操作哪些文件 + 交付什么样的结果**

> **视频里的实例**：让豆包把 8 月份收入**整理成表格放到桌面** → 回头看手机时，它已经**自动打开 Excel**，把
> **商务收入 / 小程序收入 / 咨询和知识付费** 四类分得清清楚楚，表格直接存到了电脑桌面。

**硬条件**：**电脑必须开着** —— 这不是可选项，是本地模式的前提。

---

## 3. 云电脑模式：什么时候用

- **不需要家里电脑开机**；任务在云端跑，**发出去就可以先去做自己的事**，之后再回来看进度和结果。
- **视频里的实例**：路上临时想了解"**最近 3 个月有哪些办公 AI 产品**" → 手机发任务 → 云端调研 → 回家验收。
- **不能做的**：读不到关机电脑里的文件 —— 所以**别把"帮我改一下桌面那张图"派给云电脑**。

## 4. 派单公式（本技能第零步的远程版）

远程派单失败的头号原因不是工具，是 **brief 不清 —— 你不在旁边，它没法问你。**

所以远程派单**必须把这两件事写死**（正好对应四句公式里的「任务目标 + 输出要求」）：

```
要操作哪些文件：【绝对路径 + 文件名】
交付什么结果：【格式 + 存到哪 + 命名规则】
```

对照本技能第零步：**「约束条件」那一栏在远程场景尤其不能省**（算力、比例、张数、目录、命名），因为现场没人能纠偏。

### 视觉任务的远程派单模板

```
输入：F:\项目\<项目名>\白模_v3.png（硬约束：不改墙体结构）
任务：出 3 张夜景效果图
约束：本地 5080 跑 flux1-dev fp8、CFG=1.0、steps 24、1920×1080、3 张、光影统一
输出：每张给中英提示词 + 本地参数 + 12 维自查结果
     成图存到 F:\项目\<项目名>\out\<日期>_夜景_01..03.png
```

## 5. 与「自主执行模式」的对接

```
（在公司 / 健身房 / 路上）手机派单
   → 本机批量出图 + 自动 12 维审稿
   → 手机上选稿（翻完每一张原图）
   → 回话精修 / SMART REPAIR
   → 回家只看最终稿
```

**验收纪律照旧，且远程更要强调**：远程最容易犯的错是**"没看到图就当真"** ——
**手机上必须翻完每一张原图**，再点选终稿；没看到真实结果不得标「已通过」。

## 6. 边界与坑

| 项 | 说明 |
|---|---|
| **电脑开机** | 本地模式硬条件。**建议配远程唤醒 / 防休眠**，否则人不在家就派不了单 |
| **账号** | 手机与电脑**必须是同一个豆包账号** |
| **云电脑读文件** | 读不到关机电脑的文件；带本地文件的任务只能走本地电脑模式 |
| **长任务** | 云电脑任务可以"发出去先干别的"，但要能回来看进度 |
| **显存与队列** | 本机渲染任务要留意显存占用；盘点与排队见 `田伟平设计总监大师级别/references/local-compute/` |
| **状态标注** | 视频为博主个人体验，**未在本机实测该连接流程** → 本文件标 **待验证** |

## 7. 视频没说、但本技能要补的三条

1. **出图任务的模型与参数必须随单交代**（CFG / steps / 尺寸 / seed）—— 否则远程出的图和你预期不是一回事，人不在现场改不动。
2. **批量任务必须约定命名与目录** —— 否则回家面对一堆 `output_001.png` 无从选稿。
3. **重任务要排队** —— 远程连派多条重活会撞显存；先盘点再派单，用 `local-compute/` 的脚本。

## 8. 一句话总结

> **电脑开着 + 同一账号 + 连接本地电脑 → 手机就能派单。**
> **要动本机文件、要出图 → 本地电脑模式；不带本地文件的调研 → 云电脑。**
> **派单写死「操作哪些文件 + 交付什么结果」，不然远程就是白等。**

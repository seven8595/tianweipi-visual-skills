# 自主执行：能力探测与经验记录模板

## 一、首次电脑操作能力检查清单

只查当前任务需要的项，不扫整台电脑。每项标注：A 已验证可用 / B 工具存在未验证 / C 当前无此能力。

| 能力 | 验证方法（无害操作） | 状态 |
|---|---|---|
| 读用户指定文件夹 | `ls` 目标目录 | A/B/C |
| 创建并回读文件 | 写一个临时文件再 Read | A/B/C |
| 执行命令/脚本 | 跑 `--version` 或 echo | A/B/C |
| 截屏/看屏幕 | 截一次屏并 Read | A/B/C |
| 控制键鼠/应用 | 聚焦一个已知窗口 | A/B/C |
| 联网 | 一次轻量请求 | A/B/C |
| 生成图片 | 出一张测试图 | A/B/C |
| 处理音视频 | 读一个素材元数据 | A/B/C |
| 导出文件 | 导出后回读校验 | A/B/C |

缺能力时的降级：能给可运行脚本就给脚本；否则给最短人工步骤（≤3 步），不反复要用户做无关检查。

## 二、确认边界速查

可自主（已授权范围内）：读资料、建目录、改副本、命名新文件、预览、跑可检查脚本、渲染导出验证、修常规错误。

必须先问：付费/预算、对外发布、永久删除/覆盖唯一原件、装软件/改系统设置、私素材外传、关键方向冲突大返工。

## 三、失败分类

输入问题 / 权限问题 / 路径问题 / 软件版本问题 / 资源不足 / 网络问题 / 工具不支持 / 方法不适合。

同方法连挂两次：停 → 读错误 → 缩范围 → 换路径。

## 四、经验记录模板

```
适用任务：
触发条件：
方法：
证据：（哪次任务、结果如何）
限制：
验证日期：
置信度：用户明确偏好 / 暂时推测 / 已验证有效 / 待验证
```

升级为默认流程前必须：小样验证 → 对比质量/耗时/成本/失败率/用户介入次数 → 保留或回退。

## 五、交付整理清单

- 可直接使用的成果；
- 文件名清楚；
- 标注最终版本；
- 保留源文件与可恢复版本；
- 标记未验证项；
- 给出下一步最有价值的一个行动。

# 动态工作流推导

## 核心原则
**不要从领域生命周期出发（研究→创作→发布→分析），要从用户最终结果和当前起点出发。**

## 反推法
1. 用户说"做完了"的可观察结果是什么？
2. 这个结果出现之前，必须满足什么条件？
3. 什么输入/决策/权限/转换能满足这个条件？
4. 重复直到到达用户已有的东西
5. 正向走一遍确认每步产出是下步输入

## 任务特性识别
- 一次性还是重复？
- 创作/决策/转换/协调/监控？
- 本地/外部读/外部写？
- 人主导/AI辅助/全自动？
- 单系统/多系统？
- 可逆/不可逆？
- 错了后果大不大？

## 拆分规则
**拆一步当它包含：**
- 两个独立可替换的动作
- 同时读和外部写
- 不同账号权限
- 审批+审批后动作
- 不同成功条件的输出
- 危险动作混安全动作

**停止拆分当一步有：**
- 一个非技术用户能理解的动作
- 一个主要结果
- 一个访问/副作用边界
- 一个可观察成功条件

## 内部能力卡
```yaml
goal: 用户可见结果
input: 步骤前已有什么
operation: 一个标准化动作
output: 步骤产出什么
constraints: []
frequency: 一次性|重复|事件驱动
access: 本地|外部读|外部写
approval: 无|访问前|花钱前|外部写前
success: 可观察通过条件
fallback: 不可用时替代方案
```

## 跨切面需求检查
| 需求 | 问自己 | 能力 |
|---|---|---|
| 质量风格 | 需要特定语气/质感吗？ | 润色、品牌语气、校对 |
| 准确性 | 不实事实会造成伤害吗？ | 事实核查、引用验证 |
| 合规 | 平台/版权/广告规则适用吗？ | 合规审查 |
| 隐私安全 | 涉及私密数据/密钥吗？ | 脱敏、权限审计 |
| 本地化 | 需要语言/文化适配吗？ | 翻译、本地化 |
| 数据质量 | 会重复/格式不一致吗？ | 去重、校验 |
| 协调 | 需要交接/定时/审批吗？ | 工作流、调度 |
| 可见性 | 需要监控失败/结果吗？ | 日志、监控 |

## 充分性检查
流程够详细当每步都有：
- 明确结果
- 至少一个有意义的搜索表述
- 访问和审批分类
- 是/否成功条件
- 用现有skill/新skill/工具/不需要额外能力的理由

**如果生成的流程和之前例子太像，扔掉重新从当前结果推导。**

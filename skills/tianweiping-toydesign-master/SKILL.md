## 2. A 角色 IP 设计

### 2.1 五阶段工作流

```
研究与主题 → 创意探索 → 主方案 → 系统延展 → 精修交付
```

| 阶段 | 交付物 | 关键动作 |
|---|---|---|
| 一 研究与主题 | 简短研究卡 + 创作命题 | 按一个明确创作问题选艺术家 |
| 二 创意探索 | 2-3 个**表达逻辑不同**的小稿方向 | 换轮廓/行为/材质，不只换颜色帽子职业 |
| 三 主方案 | 核心角色或主视觉 | 验证构图、结构、情绪 |
| 四 系统延展 | 转面、表情、动作、场景、产品适配 | 按实际用途做，不一次铺全套 |
| 五 精修交付 | 统一笔触/色彩/边缘/文件规格 | 修复 AI 痕迹，保留用户有意的个性 |

**每次推进只解决一个关键问题，不无限扩展。**

### 2.2 先区分原创与既有 IP

- **原创**：可探索轮廓、比例、性格、配色、标志性特征
- **既有 IP**：锁定比例、五官、纹样、结构、色彩。新动作/场景/衍生**不擅自改变角色身份**

### 2.3 角色卡（从内核出发，不堆标签）

它是谁；最想得到什么；最害怕什么；平时怎样行动；独特小习惯；观众为什么陪伴它。

**性格必须影响造型**："谨慎但好奇" → 收拢姿态、前探重心、停顿、试探动作。不能只写在简介里，要体现在体块和表演上。

**不要默认**大眼睛、圆脸、短四肢、渐变色、满身装饰——可以用，但必须服务角色意图。

### 2.4 角色标准卡（每个角色维护一版）

| 字段 | 记录内容 |
|---|---|
| 身份 | CHARACTER_ID、版本、名称、定位、欲望与性格矛盾 |
| 体块 | 总高相对单位、头身关系、躯干四肢比例、站姿重心 |
| 面部 | 眼位间距、鼻嘴形状、面部区域边界；无此部件明确写"无" |
| 标记 | 形状、数量、精确位置；左右以角色自身为准 |
| 色彩 | 主色/辅助色/点缀色及分布 |
| 材质 | 各部位材质、软硬、粗糙度、接缝/关节表现 |
| 表演 | 默认姿态、动作习惯、情绪表达、允许及禁止的变形 |
| 锁定项 | 不可变身份特征；可变的表情/动作/服装/道具 |
| 依据 | 参考文件、已认可主稿、版本状态、待验证问题 |

### 2.5 三视图与表情动作

- 正面 + 指定侧面 + 背面，**同比例、同基线、中性姿势、同镜头高度，尽量无透视**
- 四分之三视角另列，**不替代**侧面
- 跨视角检查：眼线、肩线、腰线、脚底高度、头部深度、耳/角连接、尾巴根、色块绕体方向、接缝归属
- **背面看不到五官时，不复用正面描述生成背面脸**
- 表情通过眼睑、嘴形、头姿、身体共同表达，不是每个表情换一张脸
- 动画动作拆：预备 → 主动作 → 缓冲/停顿
- 视频查起止帧和运动过程：部件增减、穿插、滑步、材质漂移、左右标记翻转

### 2.6 玩具化与衍生

先分**动画版 vs 实体概念版**，记录简化点和保留的身份锚点：

- **毛绒**：体块缝合、绒毛对小表情的遮盖、刺绣表达
- **硬质摆件**：支撑、悬挑、薄小部件、分件、涂装边界
- **可动玩具**：关节位置对轮廓与动作的影响

这些是**设计审查项，不是量产结论**。

### 2.7 面向豆包的提示词组织

不臆造豆包参数、固定种子、参考权重、独立负面栏能力。

**静态角色模板**
> 任务：根据所附角色主稿制作【本次唯一目标】。角色固定设定：【实际可见的体块、脸部关系、角色自身左右标记、配色分布与材质】。本次视角与姿势：【明确描述】。构图：【全身/局部、主体占比、留白】。照明与背景：【便于识别结构的安排】。保持：【本次必须保留的特征】。只调整：【已授权项目】。避免：【针对该图的具体缺陷】。

**动作模板**
> 使用已认可角色【ID/版本】与参考画面。固定外形与材质：【可见锚点】。起始姿态：【姿态与接触关系】；预备动作：【行为】；主动作：【方向与幅度】；结束：【停稳姿态】。镜头：【机位及是否运动】。场景：【必要信息】。变形规则：【软硬部位与范围】。检查重点：【接触、支撑、左右标记、部件数量等】。

**一个提示词只安排一个清楚的生成目标。**

### 2.8 系列开发三层规则

- **固定项**：角色身份、核心比例、识别特征、关键配色、世界观约束
- **变化项**：动作、表情、场景、视角、道具、具体故事
- **例外项**：节日/限定/实验作品中允许改变的内容

每张系列作品承担不同表达任务，避免重复"居中角色 + 装饰背景"。

**检验 IP 能否持续产生内容**：为角色写三个不同的日常小故事，检查是否都体现同一性格 / 是否有不同动作情绪 / 是否不靠新增复杂设定也能成立。如果只能想出换衣服/换颜色/换场景，说明角色行为与内在动机不充分。

## 4. C 数字绘画全流程

```
参考收集 → 构图草稿 → 线稿 → 铺大色 → 体积塑造 → 细节刻画 → 质感收尾
```

| 阶段 | 占比 | 关键动作 |
|---|---|---|
| 参考收集 | 10% | 找 3-5 张参考，分析构图/配色/笔触 |
| 构图草稿 | 10% | 剪影、大形、重心、视觉动线 |
| 线稿 | 15% | 外轮廓粗，内线细，结构准确 |
| 铺大色 | 15% | 分大色块，不抠细节 |
| 体积塑造 | 25% | 亮部暗部，光源统一，材质区分 |
| 细节刻画 | 20% | 五官、道具、纹理、边缘 |
| 质感收尾 | 5% | 整体调色，噪点/纹理，统一氛围 |

**构图原则**：三分法 / 视觉动线 / 正负形 / 对比（大小·明暗·冷暖·繁简）/ 均衡不对称

**色彩**：互补色（强对比）／邻近色（和谐）／三色（丰富）／单色（高级）。光源配比 **主光 70% / 辅光 20% / 轮廓光 10%**。

**厚涂五招**：① 干画笔/厚涂笔刷/粉笔 ② 多层叠加不一次涂匀 ③ 笔触顺结构/材质方向 ④ 焦点处实、远处虚 ⑤ **不要磨皮**，保留笔触肌理。

**素描结构基础（造型底层语法）**
1. **动态线**：一条线从头贯穿脊柱到脚，捕捉整体动势。AI 图角色僵不僵先看这条线
2. **块面化**：头颅=球、胸腔=楔形、骨盆=蝴蝶形、四肢=圆柱、关节=小球
3. **透视**：一点/两点/三点/五点（鱼眼）
4. **椭圆定方向**：圆形越接近边缘椭圆越窄，短轴对齐消失方向
5. **近大远小 + 近实远虚 + 遮挡**

**AI 生成图结构检查清单**：动态线通不通 / 三大体块关系 / 关节位置和遮挡 / 手脚透视椭圆方向 / 前后遮挡物理依据

**儿童绘本风**：造型圆润无棱角 / 颜色温暖明亮 / 笔触可见但不杂乱 / 角色夸张可爱 / 构图简洁留白 / 情绪温暖治愈

## 6. SEVEN 个人风格语言（手绘铅笔/彩铅）

> 详细档案见 `references/seven-style-profile.md`

**质感**：交叉排线画体积，不追求平滑渐变；边缘有手写感，不画干净矢量线；保留笔触层次，不全局模糊/磨皮。
**禁止**：3D 光滑渲染、数字粉系平涂、滤镜统一颗粒。

**排线规则**：亮部稀疏顺形体；暗部密集交叉叠色 2-3 层；焦点（眼睛、宝石）整块压重不打圈。

**眼睛是第一重点**：永远画得最重——整块墨色压黑，或大而圆带高光；眼神有故事（斜睨、直视、含泪、发呆）。
**禁止**：愤怒皱眉、挑眉、凶狠眼神。眉毛角度放平，表现好奇/谨慎，不表现攻击性。

**密集装饰围绕主体**：主体周围要有装饰呼应（雨滴、蝴蝶、宝石、花纹、建筑局部）。**禁止**空背景居中站姿。

**配色倾向**：暖黄/橙做主体，冷色或宝石色做点睛。**禁止**全灰阶无倾向、马卡龙粉系光滑插画。

**情绪：安静内省**——窗前看月、贴电话、含泪蝴蝶、空静物，克制带一点忧郁。不画热闹、不画动作戏。

**静物功底**：透明材质高光要准、金属明暗交界线清晰有磨损感、木头纸柔和排线。

## 7. E AI 痕迹诊断与修复

用户说"像 AI"时，结合实际作品检查，**只列最影响作品的三个问题**。

**诊断清单（按顺序查）**
1. **造型模板化**：是否落入通用 AI 角色套路（大眼圆脸渐变满身装饰）
2. **结构矛盾**：头颈、肩臂、手掌手指、腿脚、尾巴躯干的连接
3. **材质光影无依据**：高光/阴影方向是否统一
4. **细节随机**：纹路、小零件、装饰、反光是否承担作用
5. **笔触机械**：是否全局统一颗粒感、全局锐化或全局模糊
6. **拼接感**：主体与背景是否像不同作品拼的
7. **文字图案扭曲**：文字、纹样、logo 是否可读正确
8. **表情空泛/姿态僵硬**：表情是否只有嘴变，身体不参与

**先结构后表面**：检查连接关系和受力；动作必须有重心、支撑、清楚受力；手握道具要接触、遮挡、抓握，不用模糊装饰盖错误。**局部精细不能抵消整体结构错误。**

**笔触跟随形体**：笔触方向帮助表达体块、动作、空间；不随机制造脏边、错位、不对称假装人工痕迹；用户原稿中有意的简化、夸张、节奏要保留。

## 8. F 本地 ComfyUI + Flux dev img2img 精修

> 详见 `references/local-flux-refine.md`

### denoise 选型表（5080 实测）

| denoise | 效果 | 适用 |
|---|---|---|
| **0.15-0.30** | 几乎不动结构，只刷材质笔触 | ✅ 精修 / 去 AI 味 / 面部修复 |
| 0.30-0.45 | 大构图在，细节小改 | 换光影 / 微调 |
| 0.45-0.65 | 大姿势在，细节重生成 | ⚠️ 风格迁移，但易崩角色 |
| 0.65-0.85 | 只保留大致构图 | ❌ 只适合重构图 |
| 0.85+ | 仅松散参考 | 不用于 IP 衍生 |

**核心规则**：**精修用 0.25-0.30，重绘才用 0.55-0.65**——选错直接崩。

### 什么时候**不该**用生图模型

| 任务 | 正确做法 | 错误做法 |
|---|---|---|
| 已有成品 IP 图，只改画幅/加效果/upscale | PIL pad + LANCZOS 放大 + 加倒影 | Flux img2img（必崩角色） |
| 已有成品 IP 图，想换笔触风格 | 直接用原图加纹理/滤镜 | 高 denoise 让 Flux 自由发挥 |
| 真正的新构图/新姿势 | Flux 文生图或低 denoise img2img | — |

### 工作流节点

`UNETLoader(fp8_e4m3fn)` + `DualCLIPLoader(clip_l + t5xxl, type=flux)` + `VAELoader(ae)` + `KSampler(cfg=1.0, euler, simple, steps=20-26)` + `FluxGuidance(3.0-4.0)`

### Prompt 写法教训

- Flux dev **不吃** `impasto oil painting / palette knife / canvas texture` 强油画词——会输出光滑数字插画
- Flux 擅长 `soft fluffy fur, dreamy hazy lighting, creamy yellow, children's book illustration`
- **cfg=1 时 negative 不生效**，要靠 positive 把方向钉死
- 保角色时 prompt 第一句必须 `preserve the exact character, pose and composition from the input image`

### 600 DPI 交付流程（PIL 路线，不占 GPU）

```
原图 → LANCZOS 放大到目标像素 → 贴到目标比例画布
→ 底部 pad 区加高斯模糊倒影 → save(PNG, dpi=(600,600))
```

- 3:4 竖版 600DPI 推荐：2400×3200 或 4608×6144
- 2× 以上放大应用 ESRGAN 模型，不是 PIL

### 队列管理

- 提交前先 `GET /queue` 看 running/pending
- 插队：`POST /queue {"delete": ["<prompt_id>"]}` 清前面的 pending
- **不要 `/interrupt` 当前 running**（会毁正在跑的任务）

## 9. G 图片与视频制作规范（通用生产线）

> 来源：原 `doubao-visual-production` v3.0。这一层负责**把"更智能更完美"落实到可执行决策、可靠计算和真实作品验收**。

### 决策顺序（五步）

1. **锁定目标**：画面要让人看懂、感受或记住什么；必须保留什么
2. **拆解约束**：把事实、视觉身份、尺寸时长、预算和偏好分开，先消冲突再提交
3. **选择手段**：新概念用生成；已认可图优先局部编辑；准确文字与标志优先排版/合成；连续动作先检验短镜头
4. **控制试错**：先检查最大风险；高风险或需批量复用时先做一个代表性预览，不硬性要求多方案多轮审批
5. **依据结果返修**：只改失败区域/镜头/环节；**连续两轮相同方法无改善就换方法**，保留已通过版本

建立**能力卡**：产品入口、模型版本、参考输入、编辑方式、可设参数、生成工具、播放与听音能力、预算来源。**未知写未知。**

豆包聊天、即梦、火山方舟 API、本地 ComfyUI 是**不同执行入口**，参数不可直接互套。

### 分流

| 收到什么 | 读哪个 |
|---|---|
| 商业主视觉 / 建筑室内效果图 / 成套物料 / 总监审稿 | `references/visual-direction.md` |
| 咖啡店/餐厅/商业空间效果图（5 种已验证类型） | `references/commercial-space-cases.md` |
| 图片/插画/海报/角色图/产品图/效果图 | `references/image-workflow.md` |
| 分镜/漫剧/广告/动画/图生视频 | `references/video-workflow.md` |
| 实际图像视频、需要审稿返修 | `references/quality-and-repair.md` |
| 技术参数核验 | `references/capabilities-and-sources.md` |

### 项目数据校验（本地 Python，标准库，不联网）

```
python scripts/check_project.py --stage delivery --probe --ffprobe <实际路径>
python scripts/build_handoff.py       # 生成结构化制作/返修交接
python scripts/probe_media.py         # 调用已有 FFprobe 检查媒体规格
```

- 用有理数处理帧率，用整数帧表示时间线，扣除叠化重叠；**禁止凭标题推断总时长**
- 校验编号唯一、角色/参考素材引用、字幕边界、同轨重叠；朗读速度只作可配置提示
- 交付模式检查本地文件和 SHA256；评审记录必须对应同一版本，过期记录不能复用
- **工程通过与视觉通过分开**。脚本无法判断美感、变脸、手部结构或动态流畅；计算报告≠审美评分
- 探测的是容器/流元数据，**不能代表完整解码、动态播放、试听或视觉验收**

### 验收顺序

**正确性 → 结构与连续性 → 表达 → 文件规格**。关键失败不允许被其他优点平均掉；未知项不打合格分。

返修单格式：**位置 — 问题 — 影响 — 修改 — 保留 — 验收**。

经验只在真实制作后保存：问题、修改前后文件、保持与改变的条件、观察结果、用户反馈、适用范围。**安装技能、重复自评和读取资料不能算作品提升证据。**

## 10. G2 界面/网页审美校准（UI）

> 完整规则见 `references/ui-aesthetic.md`

**AI 默认配色 = 立刻廉价**：紫蓝渐变 `#667eea → #764ba2`、全屏深色+霓虹青边框、文字用纯黑 `#000` / 纯灰 `#999`。

**三色制 + 中性色阶**：主色 1 个占 60% ／强调色 1 个占 5% ／中性色 5 级灰阶占 35%。

| 用途 | 色值 |
|---|---|
| 页面背景 | `#FAFAF9`（暖白，不是纯白） |
| 主文字 | `#1C1917`（不是纯黑） |
| 次要文字 | `#78716C`（暖灰） |
| 边框 | `#E7E5E4` |
| 主按钮 | 深色 `#1C1917` 底 + 白字（**不是蓝色**） |
| 强调 | 橙 `#EA580C` / 墨绿 `#166534` / 酒红 `#9F1239` |

**8px 间距网格**：所有间距必须是 8 的倍数（4/8/16/24/32/48/64）。**禁止** 13px、17px 这种奇数间距。

**字号层级**：Display 57 / H1 45 / H2 36 / H3 28 / H4 24 / Body 16 / Small 14 / Caption 12。

**组件**：卡片圆角 12px、阴影极淡 `0 1px 3px rgba(0,0,0,0.05)`、内边距 24px；导航高 64px 固定顶部+模糊背景。

**动画**：缓动 `cubic-bezier(0.4,0,0.2,1)`，时长 200-300ms，hover 微抬升 `translateY(-2px)`。**不做**粒子、视差、1 秒以上动效、放大 1.2 倍。

**布局**：容器最大宽 1200px 居中；section 间距 80-120px；正文左对齐；留白比内容多（内容 60% / 留白 40%）。

**出代码后 Checklist**：配色不是默认蓝紫？主按钮是深色？间距都是 8 的倍数？字号有层级？留白够？圆角统一？阴影极淡？动效克制？文字用暖灰？容器有最大宽度？

**角色死抠细节标准**

| 部位 | 标准 |
|---|---|
| 体型 | 橙黄蓬松毛绒，二头身，圆肚短腿 |
| 犄角 | 彩虹螺旋双角，红→橙→黄→绿→蓝→紫分段；角根有蓝绿色小卷芽 |

| 披风 | 红色短披风，脖子红色圆珠扣 |
| 胸口 | 1 颗大发光五角星 + 周围 3 个小星光点 |

| 手 | 每只 **4 根**白色圆钝尖爪 |
| 脚 | 红色圆头小鞋，鞋口蓝绿边，每脚 3 根黄色三角爪 |
| 尾巴 | 彩虹条纹长尾巴，上方一排黄色三角背鳍，尾尖收尖不加彩球 |
| 毛发 | 有粉色彩色挑染 |

**常见错误（必查）**：① 脚画成熊猫脸拖鞋——错！是红鞋蓝绿边+3 黄三角爪 ② 胸口画成小五角星——错！是发光大星+周围小星 ③ 手画成 3 根爪——错！是 4 根白爪 ④ 背鳍画成彩色——错！是黄色三角 ⑤ 犄角根没有小绿芽 ⑥ 手环画成普通条纹 ⑦ 毛发没有粉色挑染

**ERR-ART-001 强制规则（永久生效）**
1. AI 出图**仅作草图，禁止直接交付原始 AI 图**
2. 手部必须 PS 重绘：5 根手指、关节透视正确、手掌比例协调
3. 交付前必须逐项打勾自检清单
4. 倒立姿势重点检查：重心、脖子弯曲度、衣服褶皱方向、头发因重力垂落

**画风标准**：厚涂油画 impasto 笔触，可见画布纹理 / 儿童绘本质感 / 暖黄奶油背景 / 纯 2D 禁 3D 禁 AI 光滑 / 300DPI

## 12. 审美判断与交付

### 审美判断六维

| 维度 | 问什么 |
|---|---|
| 意图 | 作品想表达什么，看不看得出来 |
| 独特性 | 是否有属于这个项目的选择 |
| 整体性 | 造型、色彩、笔触、叙事是否互相支持 |
| 取舍 | 焦点明确，细节有主次 |
| 完成度 | 结构与制作是否可靠 |
| 延展性 | 进入其他载体后是否仍成立 |

不把写实、精细、复杂、低饱和自动视为更高级。
**验收顺序**：身份结构 → 跨视角一致 → 表情动作可读 → 材质与应用适配。

### 审美建议五要素（每条建议必含）

**问题位置 / 可见依据 / 具体改法 / 预期作用 / 可能损失**

> 例："缩小右侧装饰，保留人物手势周围的空间，使动作更易读。"
> 禁说："更高级、更有大师感、更像某艺术家。"

### 参考优先级（硬顺序）

1. 当前项目与客户硬性要求
2. 用户当前明确指令
3. 用户已确认的个人风格规则
4. 用户原稿中可观察的创作特点
5. 外部参考方法

既有 IP 项目必须保持原角色标准；个人表达只能进入获允许的范围。
**外部收藏图只证明兴趣，不证明用户已形成该风格；AI 生成图不算用户亲笔创作证据。**

### 状态标注

待制作 → 制作中 → 已生成待检查 → 已检查需修改 → 已通过。**没看到真实结果不得标"已通过"**；不能播放的视频不得称节奏合格；没导出的文件不得称成品完成。

# 艺术创作工作室

## 1. 绘画工作流程

```
参考收集 → 构图草稿 → 线稿 → 铺大色 → 体积塑造 → 细节刻画 → 质感收尾
```

| 阶段 | 占比时间 | 关键动作 |
|---|---|---|
| 参考收集 | 10% | 找3-5张参考图，分析构图/配色/笔触 |
| 构图草稿 | 10% | 剪影、大形、重心、视觉动线 |
| 线稿 | 15% | 外轮廓粗，内线细，结构准确 |
| 铺大色 | 15% | 分大色块，不抠细节 |
| 体积塑造 | 25% | 亮部暗部，光源统一，材质区分 |
| 细节刻画 | 20% | 五官、道具、纹理、边缘 |
| 质感收尾 | 5% | 整体调色，噪点/纹理，统一氛围 |

## 2. 构图原则

- **三分法**：主体放在九宫格交点上
- **视觉动线**：引导观众眼睛从主焦点扫到次焦点
- **正负形**：主体和留白都要好看
- **对比**：大小对比、明暗对比、冷暖对比、繁简对比
- **平衡**：不要对称，要均衡

## 3. 色彩理论

### 配色方案
| 方案 | 说明 | 适用 |
|---|---|---|
| 互补色 | 色环对面（橙+蓝） | 强对比、视觉冲击 |
| 邻近色 | 色环相邻（蓝+绿） | 和谐、统一 |
| 三色 | 等边三角形（红+黄+蓝） | 丰富、活泼 |
| 单色 | 同一色相不同明度 | 高级、简洁 |

### 光源
- **主光**：70%亮度，定方向
- **辅光**：20%亮度，补暗部
- **轮廓光**：10%亮度，勾边分离背景

## 4. 厚涂技法

1. **笔刷选择**：干画笔/厚涂笔刷/粉笔
2. **颜料堆叠**：颜色不要一次涂匀，多层叠加
3. **笔触方向**：顺着结构/材质方向走
4. **边缘处理**：焦点处实，远处虚
5. **不要磨皮**：保留笔触肌理，不要全局模糊

## 5. 儿童绘本风要点

- 造型圆润无棱角
- 颜色温暖明亮
- 笔触可见但不杂乱
- 角色夸张可爱
- 构图简洁留白
- 情绪温暖治愈

## 6. PS快捷键

## 8. SEVEN 风格专属绘画参数（用户主创风格）

> 基于 `references/seven-style-profile.md` v0.2。接到用户原创角色/插画任务时，优先走这套参数，不要套通用厚涂。

### 8.1 质感：手绘铅笔/彩铅，不是数字光滑

| 项目 | 参数 |
|---|---|
| 笔触 | 交叉排线画体积，不追求平滑渐变 |
| 边缘 | 有手写感，不画干净矢量线 |
| 图层 | 保留笔触层次，不要全局模糊/磨皮 |
| 禁止 | 3D 光滑渲染、数字粉系平涂、滤镜统一颗粒 |

**排线规则**：
- 亮部：稀疏排线，顺着形体方向
- 暗部：密集交叉排线，2-3 层叠色
- 焦点（眼睛、宝石）：整块压重，不打圈

### 8.2 眼睛是第一重点

- 眼睛永远画得最重——要么整块墨色压黑（参考 P03），要么大而圆带高光（参考 P10 绿眼）
- 眼神有故事：斜睨、直视、含泪、发呆，不画空白眼
- **禁止**：愤怒皱眉、挑眉、凶狠眼神（A01' 已犯过）
- 眉毛角度放平，表现好奇/谨慎，不表现攻击性

### 8.3 密集装饰围绕主体（不是空背景）

- 主体周围要有装饰元素呼应：雨滴、蝴蝶、宝石、花纹、建筑局部
- 密度对标：P10（宝石眼泪+帝王蝶+珠宝项链+建筑）、R03（和风水彩少女）
- **禁止**：空背景居中站姿
- 装饰元素要和主题相关，不是随便堆花纹

### 8.4 配色倾向

- 彩铅作品：暖黄/橙做主体，冷色或宝石色做点睛
- 参考 P10：金黄头发 + 绿眼 + 橙黑蝴蝶 + 红绿宝石泪
- 参考 P01：暖肤色 + 冷蓝外套（冷暖对比）
- **禁止**：全灰阶无色彩倾向、马卡龙粉系光滑插画

### 8.5 情绪：安静内省

- 窗前看月、贴电话、含泪蝴蝶、空静物——克制的、带一点忧郁
- 不画热闹、不画动作戏
- 构图偏静态，人物朝向/视线引导观众进入情绪

### 8.6 静物功底支撑道具可信度

- 透明材质（玻璃/瓶）：高光要准，反光要有依据
- 金属（勺/灯）：明暗交界线清晰，有磨损感
- 木头/纸：柔和排线，不要画成塑料
- 角色道具要可信，不糊弄

## 10. 本地 ComfyUI + Flux dev img2img 实战红线（2026-10 龙鳞宝贝项目踩坑总结）

### 10.1 核心判断：什么时候**不该**用生图模型

| 任务 | 正确做法 | 错误做法 |
|---|---|---|
| 已有成品 IP 图，只改画幅/加效果/upscale | PIL pad 到目标比例 + LANCZOS 放大 + 加倒影/渐变 | Flux img2img 重绘（必崩角色） |
| 已有成品 IP 图，想换笔触风格（无 IPAdapter） | 直接用原图，加纹理叠加 / 后期滤镜 | 高 denoise 让 Flux 自由发挥 |
| 真正的新构图 / 新姿势 / 新场景 | Flux 文生图或 img2img 低 denoise | — |

**关键教训**：用户说"参考 A 图的画风生成 B 图"，如果 A 和 B 已经是同 IP 同风格的成品图（比如同一角色的两张插画），那 B 本身就已经是目标风格，不需要重绘。直接 pad + upscale 即可。重绘只会把角色特征画崩（角变光滑螺旋、尾巴变刺尾、身体变鳞片、多签名、丢肚子斑点）。

### 10.2 Flux dev img2img denoise 选型表（5080 16GB 实测）

| denoise | 效果 | 适用 |
|---|---|---|
| 0.35-0.45 | 几乎不动，仅调色/微调光影 | 后期调色 |
| 0.5-0.6 | 保留构图和主要特征，材质有变化 | 风格微调但要保角色 |
| 0.65-0.75 | 构图在但细节跑偏（手指、装饰、小特征丢失） | 不推荐用于已有 IP |
| 0.8+ | 完全自由发挥，角色放飞（变恐龙/加签名/丢彩虹条纹） | 只适合重构图 |

### 10.3 本地 ComfyUI 操作套路（Windows + 5080）

- ComfyUI 默认跑在 `http://127.0.0.1:8188`，API 直接 POST `/prompt`
- **不要走云端生图工具**（image_gen/image_edit），用户硬约束本地算力
- 模型位置：`F:\AI\ComfyUI\models\`，当前有 `flux1-dev.safetensors`（fp8）、`t5xxl_fp8`、`clip_l`、`ae.safetensors` VAE
- 工作流：UNETLoader(fp8_e4m3fn) + DualCLIPLoader(clip_l + t5xxl, type=flux) + VAELoader(ae) + KSampler(cfg=1.0, euler, simple, steps=20-26) + FluxGuidance(3.0-4.0)
- 显存 16GB 跑 1152×1536 fp8 没问题，但如果队列被别的任务占满，先查 `/queue`，别直接提交
- 队列有别的会话插队时，用 `POST /queue {"delete": [prompt_id...]}` 删前面的 pending，不要 `/interrupt` 当前 running（会毁正在跑的任务）

### 10.4 600 DPI 交付流程（PIL 路线，不占 GPU）

```
原图 → LANCZOS 放大到目标像素宽（如 4608）→ 贴到 3:4 奶油黄画布
→ 底部 pad 区加高斯模糊倒影（flip + GaussianBlur + 渐变 mask）
→ save(PNG, dpi=(600,600))
```

- 3:4 竖版 600 DPI 推荐像素：**2400×3200**（印刷 4×5.3 英寸）或 **4608×6144**（7.7×10.2 英寸，A4 级）
- 原图小于目标尺寸 2 倍以上时，用 LANCZOS + UnsharpMask(radius=1.2, percent=60) 抵消软化
- DPI 只是元数据标记，实际清晰度取决于原图分辨率，不要指望放大凭空变清晰

### 10.5 Prompt 写法教训

- Flux dev **不吃** "impasto oil painting / palette knife / canvas texture" 这类强油画词——它会输出光滑数字插画
- Flux 擅长的是 "soft fluffy fur, dreamy hazy lighting, creamy yellow, children's book illustration"
- 不要写 "NOT ..." 负向词，cfg=1 时 negative 不生效；要靠 positive 把方向钉死
- 要保角色时，prompt 第一句必须是 "preserve the exact character, pose and composition from the input image"

## 11. AI 绘画方法论精要（2026-10-06 全网学习+今晚实战沉淀）

### 11.1 Flux dev img2img denoise 完整选型表（实测+社区校准）

| denoise 区间 | 任务类型 | 结构保留度 | 今晚龙鳞宝贝验证 |
|---|---|---|---|
| **0.15-0.30** | 轻度精修 / 面部修复 / 质量增强 / 去 AI 味 | 几乎不动结构，只刷材质笔触 | ✅ v8=0.28 一次到位：角色全对+厚涂笔触出来 |
| **0.30-0.45** | 微妙编辑 / 换光影 / 微调细节 | 大构图在，细节小改 | 未测，下次试 |
| **0.45-0.65** | 明确风格迁移 / 换画风但保姿势 | 大姿势在，细节重生成 | ⚠️ v1=0.65 角色跑偏、v4=0.5 星星变星星套星星 |
| **0.65-0.85** | 重大转变 / 照片转绘画 | 只保留大致构图 | ❌ v2=0.82 变恐龙、v6=0.6 变小熊 |
| **0.85+** | 完全重新生成 | 仅松散参考 | 不用于 IP 衍生 |

**核心规则**：
- **精修（只加质感）用 0.25-0.30，重绘（改姿势）才用 0.55-0.65**——选错直接崩
- Flux 1 dev 和 Flux 2 行为不同：Flux 2 的 strength<0.8 效果极弱（社区说 0.85 才是甜点），但 Flux 1 dev 沿用传统扩散模型行为，0.28 就有明显风格化
- 低 denoise 用模糊 prompt 就行（原图做大部分工作）；高 denoise 必须详细 prompt（模型在重新生成）

### 11.2 素描结构基础（角色造型的底层语法）

任何 AI 出图的结构审查都按这套顺序：

1. **动态线（Gesture Line）**：先一条线从头贯穿脊柱到脚，捕捉整体动势。AI 图角色僵不僵，先看这条线通不通
2. **块面化（Block-in）**：
   - 头颅 = 椭圆/球
   - 胸腔 = 楔形/蛋形
   - 骨盆 = 蝴蝶形/桶形
   - 四肢 = 圆柱
   - 关节 = 小圆/球
3. **透视**：
   - 一点透视：正对主体，背景消失于中心
   - 两点透视：建筑/场景常用
   - 三点透视：仰角/俯角
   - 五点透视（鱼眼）：夸张动感
4. **椭圆定方向**：圆形越接近边缘，椭圆越窄，短轴对齐消失方向。AI 图手脚透视错，先查椭圆方向
5. **近大远小 + 近实远虚 + 遮挡**：前景打破后景轮廓，最大前景面压过细线

**AI 生成图结构检查清单**：
- [ ] 动态线通不通（重心稳不稳）
- [ ] 三大体块（头/胸/盆）关系对不对
- [ ] 关节位置和遮挡关系对不对
- [ ] 手脚透视椭圆方向对不对
- [ ] 前后遮挡有没有物理依据

### 11.3 李飞飞空间智能对 AI 绘画的指导

核心命题（2024-2026 World Labs / Marble / Atlas）：
- AI 下一个边界不是更大的语言模型，而是**空间智能**——理解位置、关系、结构、物理规律
- 当前 AI 生图/视频的根本缺陷：**不懂遮挡、不懂重力、不懂杯子掉下去会碎**，像素看起来对但几何不一致
- World Labs 的解法：生成完全可导航、可交互、**几何永久一致**的 3D 世界（不是一段"看起来像"视频的像素动画）

**对当前 AI 绘画项目的指导**：
- 审 AI 图时不只看"好不好看"，要问：**这个空间关系物理上成立吗？**（脚踩在云上有没有接触阴影？披风飘动方向和光线一致吗？星星发光的光照范围对不对？）
- 角色转面/系列图时，**一致性比单张好看更重要**——这是空间智能的初级要求
- 后续 NEONA 毕设做 3 角色虚拟 IP 时，目标不是"出 3 张漂亮图"，而是"3 个角色在同一空间规则下一致"

### 11.5 编程思维（对 AI 出图工作流的指导）

- **版本控制**：每版 workflow JSON 存文件（v1/v2/v3...），seed 固定可复现
- **小步迭代**：改一个参数跑一版，不要一次改 denoise+prompt+seed 三个变量
- **基线对比**：每版和上一版 diff，确认改动产生了预期效果
- **失败归档**：崩了的版本不删，记录为什么崩（denoise 太高/prompt 缺锚点/seed 不凑巧）
- **提示词模块化**：positive 分三段——身份锁定（preserve character）+ 风格描述 + 材质细节

| 版本 | denoise | 结果 | 教训 |
|---|---|---|---|
| v1 | 0.65 | 角色在但偏光滑 | 风格不够 |
| v2 | 0.82 | 变恐龙刺尾 | denoise 太高 |
| v3 | 0.50 | 未跑（切到 PIL 路线） | — |

### 11.7 后处理放大：PIL vs ESRGAN 超分模型

| 方案 | 适用场景 | 质量 | 速度 |
|---|---|---|---|
| PIL LANCZOS + UnsharpMask | 1.2× 以内放大、快速交付 | 可接受，会略软 | 秒级 |
| ESRGAN / Real-ESRGAN 模型（ComfyUI UpscaleLoader） | 2× 以上放大、印刷级要求 | 真超分，细节增强 | 慢（5080 约 1-2 分钟/张） |

**规则**：
- 输入图已经是 1152×1536，要放大到 4608×6144（4×）→ 应该用 ESRGAN 模型，不是 PIL
- 今晚 v8 用 PIL 4× 放大是应急方案，实际印刷时应该跑 ESRGAN 重放大一次
- ComfyUI 里加载 `UpscaleModelLoader` + `ImageUpscaleWithModel` 节点，选 4x-UltraSharp 或 RealESRGAN_x4plus

### 11.8 交付格式选择

- 可导入 Canva / 设计软件的格式：**PNG**（带透明底最好），不要 JPG（压缩痕迹）
- DPI 元数据：PIL 保存时 `dpi=(600,600)`，只是标记，不改变实际像素
- 文件名规范：`项目名-构图-版本号-尺寸-dpi.png`（如 龙鳞宝贝-云上捧星-竖版3x4-600dpi-v8.png）

### 11.9 队列管理小坑

- 提交任务前先 `GET /queue` 看 running/pending
- 如果有别的会话在跑批量任务，不要直接提交（会排队等很久）
- 紧急插队：`POST /queue {"delete": ["<prompt_id>"]}` 清掉前面的 pending（确认是别的任务再删，别删自己的）

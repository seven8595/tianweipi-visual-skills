# 质量与修复

## 状态与证据

每项用 `pass / fail / unknown`；不适用项依据项目内容排除，不通过删去检查来提高分数。没有真实媒体时状态为方案；未检查时是 unknown，不能给满分。

| 检查维度 | 实际证据 | 失败时优先处理 |
|---|---|---|
| 简报与事实 brief | 对照用户要求、真实资料与实际画面 | 修正遗漏、错误事实、需求冲突 |
| 身份 identity | 角色/产品基准和实际输出并排看 | 稳定参考及识别锚点，修复局部 |
| 结构 structure | 正常尺寸与局部查看 | 解剖、数量、透视、遮挡和接触关系 |
| 表达 composition | 正常观看尺度和明确传播目标 | 焦点、层级、明暗、留白、节奏 |
| 文字 text | 逐字核对可见文案 | 重新排字或合成准确标志 |
| 动态 motion | 播放整个镜头并记录问题时间 | 动作、闪烁、变形和穿透 |
| 连续性 continuity | 按顺序播放镜头，或对照成套图片 | 身份、方向、道具、光线与衔接 |
| 声音 sound | 实际听音 | 同步、可懂度、爆音和收尾 |
| 文件 export | 实际探测输出文件信息 | 尺寸、格式、帧率、时长等 |

脚本只能核对评审字段、文件存在与版本绑定，不能确认评审人实际看过素材或结论正确。某人声称通过时记录来源；验收者仍须完成真正观看与听音。

## 返修排序

先处理妨碍交付的事实/身份/结构错误，再处理动态、连续性与声音，最后处理细节。根据用户用途调整：产品标志错误可比轻微纹理瑕疵优先，独立插画的情绪表达也可能是核心缺陷。不以平均总分覆盖关键失败。

返修记录：

```text
任务与版本：
定位：图片区域，或 SHOT_ID + 时间段。
问题和影响：实际可见/可听证据。
必须保留：主创已认可部分。
本轮改变：最小有效修改及所用工具。
前后产物：路径、文件哈希和生成条件。
验收方式与结果：实际操作；未检部分写未知。
后续：通过则复用，失败则说明下一种手段。
```

不要求每次只变一个参数：明确的结构修复可以联动修改；需要比较原因时才控制实验条件。两轮同方法无改善就换方法，不循环抽卡直到耗尽预算。发生未知成本、服务异常或输出损坏时先查具体原因，避免盲目提交重复请求。

## 可复用经验

方法状态采用“待验证 → 局部通过 → 可复用”，失败或出现反例可以撤回。一次作品通过仅支持该任务；推广前在不同内容中检验。记录用户真实反馈，不伪造学习日志或成功率。保存新的窄规则与适用条件，保留旧版本以便回滚。

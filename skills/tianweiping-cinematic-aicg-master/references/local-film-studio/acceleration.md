# 5080 / 32GB 加速手册

本手册只针对 **32GB 显存档（RTX 5080 / 5090）**。目标是把单镜头生成时间从"FP8 原生的 4–8 分钟"压到"可挂通宵批量跑"的量级，同时不毁掉关键镜头的画质。

> 原则：**加速是 tradeoff，不是免费午餐**。下面每个手段都标了画质代价。
> 人物特写 / 情绪镜头 / 成片主力镜头 → 关掉加速，走原生质量。
> 空镜 / 过渡镜头 / 环境交代 / 废片率高的试拍 → 开最猛加速。

---

## 0. 先校准，再谈加速

**第一次跑任何加速前，必须先做一次基线测试：**

1. 选一个代表镜头（5 秒 / 49 帧 / 720p / FP8 原生 / 不开任何加速）。
2. 记录单镜头墙钟时间（ComfyUI 队列里看执行时长）。
3. 把这个数字写进项目的 `02_storyboard/shot_list.md` 顶部，作为本机基准 T0。
4. 后面每加一个加速手段，单独测一次同样的镜头，记录 T1/T2/T3 和肉眼画质差异。
5. **不要拿社区博主的速度当自己的工期依据**——驱动版本、CUDA 版本、热功耗墙、后台占用都会差出一倍。

---

## 1. 路线选择：FP8 原生 vs GGUF（32GB 直接选 FP8）

| | FP8 原生（推荐） | GGUF Q4/Q5 |
|---|---|---|
| 画质 | 接近 BF16 | 细节略糊、文字/手指易崩 |
| 显存占用 | ~20–24GB（720p） | ~12–16GB |
| 速度 | 基线最快 | 量化反序列化有开销，未必更快 |
| 适用 | 32GB 主力 | ≤16GB 兜底 |

**结论：5080 不要碰 GGUF。** 显存够还用量化版，等于自己降画质又没换速度。

---

## 2. TeaCache（特征缓存，最常用的加速手段）

**原理**：相邻帧的特征图大量重复，缓存住、隔几步再算一次。

- **装哪个节点**：ComfyUI 里搜 "TeaCache" 相关自定义节点（ComfyUI-TeaCache 或 Wan 专属 wrapper），跟你用的 WanVideoWrapper 配套。
- **怎么开**：在采样器前挂 TeaCache 节点，`rel_l1_thresh` 或 `cache_step` 是核心旋钮。
- **推荐起点**：`rel_l1_thresh ≈ 0.15`（偏质量）到 `0.30`（偏速度）。
- **画质代价**：
  - 阈值 ≥ 0.3 时，快速运动（打斗、转头、衣料飞）会出现**残影 / 拖影 / 帧间果冻感**。
  - 静态对话镜头、空镜几乎无感知。
- **使用建议**：
  - 空镜 / 氛围镜头：0.25–0.30
  - 普通叙事镜头：0.15–0.20
  - 人物大特写 / 情绪戏：**关掉**（0 或 bypass）

---

## 3. Block Swapping（层换入换出）

**原理**：把 Transformer 的部分计算层留在内存里，用哪层换哪层。

- **什么时候用**：32GB 其实不缺显存，BlockSwap 主要在你想开 **720p 同时塞 IP-Adapter / LoRA / 额外参考图** 导致显存吃紧时才需要。
- **代价**：PCIe 搬运有开销，**开了可能反而变慢**，只是用时间换不 OOM。
- **结论**：5080 日常不用开；只有真 OOM 了再上，且优先降分辨率而不是开 BlockSwap。

---

## 4. torch.compile

- ComfyUI 新版会自动尝试编译，**首次启动第一个镜头会很慢（几分钟编译）**，之后同结构工作流的镜头会快一截。
- **不要因为第一个镜头慢就以为卡死了**。挂着跑完第一个，第二个开始才是真实速度。
- Windows 上 torch.compile 偶尔出编译错误，报错就 `--disable-compile` 退掉，不要在这上面死磕。

---

## 5. 采样步数（steps）怎么砍

- Wan2.1 I2V 默认 20–30 步。
- **空镜 / 氛围**：可以试 15 步，画质损失肉眼不明显。
- **叙事镜头**：保持 20 步。
- **特写 / 关键镜头**：25–30 步，别省。
- 砍步数比开 TeaCache 对画质的伤害更均匀，优先砍步数，再开 TeaCache。

---

## 6. 批量策略（不加速也能省时间的部分）

1. **晚上挂队列**：ComfyUI 支持队列堆积，睡前把第二天要跑的镜头全排上，睡醒收片。
2. **先跑粗剪**：所有镜头用最低质量档跑一遍粗剪，剪出节奏和叙事问题，再回头精修保留下来的镜头。**不要一上来就用最高质量跑 600 个镜头。**
3. **分辨率阶梯**：
   - 粗剪阶段：480p + 15 步 + TeaCache 0.25
   - 精修阶段：720p + 20 步 + TeaCache 0.15
   - 特写镜头：720p + 25 步 + 关 TeaCache
4. **废片优先局部修**（见 production_pipeline.md），别整条重跑。

---

## 7. 反模式（别这么干）

- ❌ 一边跑 ComfyUI 一边打游戏 / 开浏览器 100 个标签页 → 显存和功耗墙双重掉速。
- ❌ 每次改一个 prompt 就重新加载模型 → 把要测的 prompt 排进队列，模型只加载一次。
- ❌ 第一个镜头就把所有加速全拉满 → 你不知道哪个手段在掉画质。
- ❌ 用 16GB 的工期表套 5080 → 按第 0 节自己实测。

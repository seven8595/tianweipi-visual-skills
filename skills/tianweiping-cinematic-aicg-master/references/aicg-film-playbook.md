## 1. 制作流程（导演工作流）

```
导演阐述 → 色彩脚本 → 角色美术设定 → 分镜剧本 → 关键帧 → 图生视频 → 剪辑合成 → 声音设计
```

| 阶段 | 工具 | 输出 | 关键质量门 |
|---|---|---|---|
| 导演阐述 | 豆包 | 对标大师列表、情绪弧、色彩脚本 | 先定风格再出图 |
| 角色设定 | Seedream | 角色标准图+磨损道具 | 不是完美脸，是被职业刻过的脸 |
| 分镜剧本 | 豆包 | 镜头表+情绪+台词+时长 | 每镜必须有情感功能 |
| 关键帧 | Seedream | 每镜头首帧图 | 逐张生成逐张交付 |
| 图生视频 | Seedance | 5秒/段动态片段 | 用首帧锁角色一致性 |
| 剪辑 | 剪映/PR | 拼接+转场+BGM | 黑场过渡比花哨转场高级 |
| 声音设计 | 剪映/免费素材 | 人声+音效+BGM | 关键时刻抽掉所有声音 |

## 2. 【实战经验】两条视觉路线

同一个剧本，出两个版本，按投放场景选：

| | 写实电影版 | 艺术厚涂版 |
|---|---|---|
| 目标 | 短视频传播、直接情绪冲击 | 影展、致敬、高级感、朋友圈 |
| 参考 | 《烈火英雄》《勇往直前》 | 安德鲁·怀斯、伦勃朗、马远留白 |
| 构图 | 满屏叙事、人物占满画面 | 大面积留白/暗部，人物只占1/3 |
| 配色 | 丰富、细节多 | 严格两色（橙琥珀#ff8c3a + 深青蓝#1a2a3a） |
| 人物 | 真实脸、疤、胡茬、汗 | 剪影、半明半暗、只见轮廓 |
| 光影 | 多点照明、环境光 | 单光源伦勃朗光、大面积死黑 |
| BGM | 弦乐推高+鼓点 | 坂本龙一式单音钢琴、无鼓点 |
| 适合 | 抖音/快手/B站 | 微信视频号/小红书/影展 |

**默认先出艺术版关键帧定调，再决定是否补写实版。**

## 3. 【实战经验】大师级Prompt公式

### 3.1 艺术版Prompt骨架

```
[艺术风格词] + [构图比例：人物占画面X分之一，X分之几留白]
+ [单光源位置和色温] + [严格配色：只允许A色和B色]
+ [笔触/肌理：厚涂油画、可见颜料肌理]
+ [情绪词：孤独/悲壮/克制/崇高]
+ [参考大师名：安德鲁怀斯/伦勃朗/西蒙斯塔伦哈格]
+ 8K
```

**实例（致敬救火英雄）：**
> 艺术厚涂油画风格。消防员抱孩子的剪影，人物只占画面下方三分之一，上方三分之二是翻涌浓烟。伦勃朗式明暗对比，人物只被身后橙琥珀色火光照亮轮廓，身体沉入深青蓝阴影。色调严格控制在橙琥珀#ff8c3a与深青蓝#1a2a3a两色。笔触可见厚涂肌理。宁静悲壮。

### 3.2 写实版Prompt骨架

```
电影级写实渲染，院线大片质感
+ [角色：年龄+职业痕迹：疤/胡茬/皱纹/磨损]
+ [装备：不是崭新的，写具体磨损位置]
+ [动作：有物理重量，不是摆拍]
+ [光影：具体光源位置+色温+丁达尔效应]
+ [参考：罗杰迪金斯摄影/是枝裕和情感]
+ 8K超高清
```

## 4. 【实战经验】角色设计反"AI脸"

AI默认会出完美小鲜肉脸。英雄题材必须刻意打破：

| 部位 | AI默认 | 英雄角色应该 |
|---|---|---|
| 脸 | 光滑无瑕疵 | 旧疤、胡茬、眼角纹、烟灰汗水混在一起 |
| 手 | 干净修长 | 老茧、指甲缝洗不净、粗糙 |
| 装备 | 崭新笔挺 | 肘部磨白、膝盖烧焦洞、水渍焦痕 |
| 眼神 | 明亮看镜头 | 平时疲惫下垂，入火场瞬间锐利 |
| 体型 | 精瘦上镜 | 肩膀宽厚、脖子粗、被工装撑满 |
| 道具 | 无 | 磨损全家福、红绳徽章、速效救心丸瓶 |

**Prompt必须写：** "面容饱经风霜""肘部磨白有烧焦痕迹""粗糙有老茧的手""不是小鲜肉脸"。

## 6. 【实战经验】情感节拍（哪些镜头真的让人哭）

经过验证的高情绪密度镜头：

1. **摘面罩给孩子**：把自己的呼吸面罩摘下来扣在别人脸上——牺牲不用台词，动作本身就是
2. **偷偷哭被人看见**：靠在轮胎上流泪，赶紧用袖子擦掉——脆弱比坚强更打动人
3. **道具呼应**：女孩怀里的蜡笔画"爸爸"和主角头盔里藏的女儿画一模一样——不用解释，观众自己会懂
4. **金句**："怕就对了。怕还往里冲，才是消防员。"——12个字，胜过30秒旁白
5. **剪影比正脸强**：英雄时刻用逆光剪影，比拍正脸流泪高级十倍

**反模式（不要做）：**
- 不要旁白说教
- 不要慢镜头+煽情BGM堆
- 不要角色对着镜头喊口号
- 不要把英雄拍成超人（要拍成会累、会哭、会手抖的人）

## 7. 镜头语言速查

### 景别与情绪
| 景别 | 情绪 | 用在哪 |
|---|---|---|
| 远景/大远景 | 宏大、孤独、人在天地间小 | 开场、结尾致敬 |
| 全景 | 交代环境关系 | 抵达火场、列队 |
| 中景 | 叙事、动作 | 救援过程 |
| 近景 | 对话、情感 | 拍肩、对视 |
| 特写 | 情绪爆点 | 摘面罩、流泪、眼神 |

### 镜头运动
| 运动 | 效果 |
|---|---|
| 缓慢推 | 强调、进入内心 |
| 缓慢拉远 | 离开、揭示孤独 |
| 手持呼吸感 | 真实、紧张 |
| 固定长镜头 | 凝视、庄重、致敬结尾 |
| 慢动作 | 情感升华、牺牲瞬间 |

**艺术版多用固定镜头+缓慢推拉，少用花哨运镜。**

## 8. 图生视频Prompt公式

```
[主体正在做什么动作，有物理重量]
+ [环境元素如何流动：火焰跃动/烟雾翻涌/水波反射晃动]
+ [镜头运动：固定/缓慢跟随/缓慢推近]
+ [节奏：安静/紧张/呼吸感]
```

**关键：** 不要让人物做大动作。5秒视频里人物只走几步、微微低头、肩膀轻颤就够了。动得越多越假。

---

## 9. 角色一致性技巧

1. **固定首帧**：每张图生视频都用同一张关键帧做首帧
2. **锁定描述词**：每次prompt里角色核心特征一字不差
3. **分段5秒**：不要一次生成太长，5秒一段
4. **先定一张核心脸**：第一张关键帧满意后，后续所有镜头都基于它的人物描述
5. **艺术版可以剪影**：剪影不用一致性，反而更高级

## 11. 节奏与时长

- **15-30秒精华版**：4-6个镜头，每个5秒，黑场过渡
- **60秒短片**：8-12个镜头，长短结合
- **艺术版节奏**：比写实版慢，每个镜头多停1-2秒，给观众消化情绪

## 12. 【实战经验】声音设计

- **关键时刻抽掉所有声音**：摘面罩瞬间，BGM和环境音全停，只剩人物呼吸——这个技巧比任何音效都强
- **环境声做床底**：火焰呼啸、城市底噪铺在最底层
- **BGM克制**：艺术版用单乐器（钢琴/大提琴），不要弦乐堆
- **掌声从一人到一片**：结尾致敬时，掌声渐起比突然响起高级
- **混音**：人声-6dB，BGM-18dB，音效-12dB

## 15. 【实战经验】本地RTX 5080 + ComfyUI MiniMax H3 渲染管线

当云端视频生成额度用完、或用户要求"本地渲染/不用算力"时，切本地H3。

### 15.1 关键路径（Windows RTX 5080 16GB）
- **活跃ComfyUI实例**：`C:\Users\seven\Desktop\ComfyUI_windows_portable\`（不是E盘那个！）
- API：`http://127.0.0.1:8188`
- H3工作流模板：`D:\AI_WORKSPACE\h3_template.json`
- 输出目录：`C:\Users\seven\Desktop\ComfyUI_windows_portable\ComfyUI\output\window_film\`

### 15.2 必须改的节点参数
| 节点ID | 参数 | 设成什么 |
|---|---|---|
| `105:11` (VAELoader) | vae_name | `minimax_h3_video_vae_int8_convrot.safetensors`（实际是fp16文件复制改名） |
| `114` (LoadImage) | image | 上传后的文件名（xxx.jpg） |
| `115` (ResolutionSelector) | aspect_ratio | `"16:9 (Widescreen)"`（不是9:16竖屏） |
| `105:104` | prompt | 英文描述，不要写中文 |
| `105:111` | value | 5.0 / 10.0 / 15.0（秒） |
| `105:15` | noise_seed | 随机整数 |
| `92` | filename_prefix | `window_film/shotXX` |

### 15.3 图片上传（必走API，不能直接复制）
关键帧图虽然扩展名是.png，但实际是JPEG数据（文件头FF D8 FF）。直接复制到ComfyUI的input目录会被LoadImage验证拒绝。必须：
```
POST http://127.0.0.1:8188/upload/image
Content-Type: multipart/form-data
字段名: image
文件名: xxx.jpg（注意改成.jpg后缀）
```
上传成功后返回 `{"name": "xxx.jpg", "subfolder": "", "type": "input"}`。

### 15.4 性能基准（RTX 5080 16GB + int8 + turbo 8步）
| 时长 | 渲染时间 | 文件大小 |
|---|---|---|
| 5秒 | ~60秒 | 300-600KB |
| 10秒 | ~180秒 | 700-1400KB |
| 15秒 | ~300秒 | 1-2MB |

- 内存是瓶颈（32GB物理，空闲需≥15GB），不是显存
- 模型加载一次后常驻内存，连续提交不用重载
- 批量提交：一次性POST所有任务到/prompt，ComfyUI自动排队
- 每段视频24fps，16:9，MP4格式

### 15.5 批量渲染模式
1. 先批量上传所有关键帧（循环POST /upload/image）
2. 再批量提交所有/prompt任务（间隔1秒）
3. ComfyUI自动排队，逐个渲染
4. 等所有任务完成后，从output目录统一复制到项目目录
5. **不要在脚本里用history API轮询**——直接等固定时间后扫output目录

### 15.6 PowerShell 5.1 坑
- `$pid`是只读自动变量，不能用作自定义变量名，用`$jobId`代替
- JSON解析用`ConvertFrom-Json -InputObject $raw`，不要pipeline传
- 节点ID带冒号用`$wf.'105:104'`访问，不要用`$wf["105:104"]`

### 15.7 云端 vs 本地决策
| | 云端Seedance | 本地H3 |
|---|---|---|
| 费用 | 按次扣费，有额度上限 | 免费，只耗电 |
| 速度 | 5秒约30秒出片 | 5秒约60秒，10秒约180秒 |
| 质量 | 风格化强，运动流畅 | 写实自然，风格化弱 |
| 额度 | 用完要等恢复 | 无限，想跑多久跑多久 |
| 适合 | 关键镜头精品 | 批量补拍、蒙太奇、日常镜头 |

**策略：关键情感镜头用云端精品，过渡/蒙太奇/补拍用本地批量。**

## 16. 20分钟长片素材规划

20分钟成片不需要20分钟原始素材。剪辑公式：
- 核心镜头（10-15个）× 10秒 = 2-3分钟原始素材
- 情绪镜头慢放0.5x → 翻倍
- 静帧定格配旁白 → 每个5-10秒
- 旁白/BGM间奏 → 每段20-30秒
- 叠化过渡 → 每个3-5秒
- 时间跳转字幕卡 → 2-3秒

**2-3分钟原始素材 + 旁白 + 音乐 + 慢放 = 20分钟成片。**

## 17. 【实战血泪】30分钟长片本地组装 + ComfyUI运维坑

### 17.1 从19个镜头撑到27分钟的剪辑公式

19个×15秒=4.75分钟原始素材，要拉到27分钟：

| 手段 | 命令 | 效果 |
|---|---|---|
| 4倍慢放 | `setpts=4.0*PTS` | 15s→60s，动作变慢有呼吸感 |
| 黑场呼吸段 | `color=c=black:d=20` | 20秒静默，给观众消化情绪 |
| 蒙太奇重播 | Act4重播Act1-3情感镜头 | 用已渲染素材撑时长，不花算力 |
| 全片慢放 | 所有镜头统一4x | 风格统一，像艺术片 |

**关键：** 4x慢放配合黑场20秒，19镜头→27分钟。节奏慢但不拖——因为每个镜头本身是情感镜头，慢放让观众沉浸。

### 17.2 ComfyUI队列积压急救

**症状：** 后台监控脚本重复提交，queue_pending=200+，新提交的任务排不上。

**急救：**
```powershell
# 1. 中断当前渲染
Invoke-WebRequest -Uri "http://127.0.0.1:8188/interrupt" -Method POST
# 2. 删pending（API有时不灵，多试几次）
$q = Invoke-WebRequest "http://127.0.0.1:8188/queue" | Select-Object -Expand Content | ConvertFrom-Json
$ids = $q.queue_pending | ForEach-Object { $_.prompt_id }
Invoke-WebRequest "http://127.0.0.1:8188/queue" -Method POST -Body (@{delete=$ids}|ConvertTo-Json) -ContentType "application/json"
# 3. 如果删不干净，重启ComfyUI最快
```

**预防：** 批量提交前先查 `queue_pending.Count`，>20就先清。不要同时跑监控脚本。

### 17.3 本机ffmpeg硬限制（C:\Program Files\Live2D Cubism 5.3\tools\ffmpeg.exe）

| 功能 | 支持？ | 替代方案 |
|---|---|---|
| libx264 | ❌ | `-c:v mpeg4 -qscale:v 2` |
| drawtext | ❌ | 标题卡用Flux出图，不用ffmpeg加字 |
| -preset | ❌ | 不写 |
| 音频滤镜(amix/sine) | ⚠️ 部分 | BGM必须用剪映/外部工具加 |
| concat demuxer | ✅ | 但concat.txt必须UTF8无BOM |

**concat.txt写入（PS5.1必用）：**
```powershell
[System.IO.File]::WriteAllLines($path, $lines, [System.Text.UTF8Encoding]::new($false))
# 不要用Out-File，它会加BOM导致"unknown keyword '﻿file'"
```

## 18. 【大师级制作方法转译】宫崎骏×新海诚×ufotable（学习自Codex animation-director-review-v2 2.1.1）

> 来源：用户从ChatGPT/Codex会话迁移的动画导演技能（animation-director-review-v2 2.1.1 + 豆包交接文档 V2）。这些是公开资料的有界转译，不是大师"配方"。写入skill不等于已训练出大师能力——必须用真实成片验证。方法编号沿用源文档便于跨工具接续。

### 18.1 先选主方向（不要三种风格强混）

| 需求 | 主方法 | 辅助 | 画面变量 |
|---|---|---|---|
| 成长/日常/善意/性格 | 宫崎骏 JM01-03 | JM04、JS02 | 行动表现成长、重量、环境跟随体验 |
| 等待/距离/记忆/地点情绪 | 新海诚 JS01-04 | JM01、JM04 | 生活痕迹、环境光、焦点、情绪停顿 |
| 危机/战斗/爆发 | ufotable JU01-04 | JM02、JS02 | 空间与关键动作先成立，特效再强调 |

### 18.2 宫崎骏/吉卜力转译

- **JM01 成长由行动表现**：写清"想做什么—遇到阻力—怎样尝试—结果怎样改变"。用同龄人能否完成的行动检验角色。幻想能力要有本作规则支撑。
- **JM02 生活参考落实重量**：搬/推/拉/放要检查支撑脚、接触点、重心移动、阻力变化、余力恢复。原速看施力与移动是否呼应。
- **JM03 体验决定环境取舍**：先写角色此刻注意什么，再安排背景/环境声/停顿。停顿要读到观察、迟疑、理解或恢复。不设固定"ma"比例。
- **JM04 Layout统一所有部门**：关键镜先定地标、比例、起止位、路径、遮挡、摄影机、光源。风雨衣发共享同一空间驱动。

### 18.3 新海诚/CWF转译

- **JS01 地点能被生活**：先固定出入口/路径/尺度，再选少量有使用原因的差异（磨损台阶、湿椅面、遗留物件）。道具在行动中发挥功能。
- **JS02 每镜呈现色受环境光影响**：每镜写"注意对象—主光—时间—天气—反射—人物明暗"。身份基准色与场景呈现色分开核对。
- **JS03 焦点与细节有分配**：每镜一个首要注意对象，按景别和观看时间分配明暗/锐度/细节。宁静场景可降对比，写明理由即可。
- **JS04 先看整段再精修停顿**：先做可播放粗剪，检查"获得信息—理解变化—发生反应"。改镜长必须同步更新对白/音乐/音效/字幕。

### 18.4 ufotable/鬼灭转译

- **JU01 演出阶段决定2D/CG分工**：逐镜决定哪些部分二维表演、哪些三维空间/重复透视，列依赖和交接。先做代表镜整合样片再推广。
- **JU02 相机与动作一起预演**：先做场景关系图/透视草稿/灰模，同时检查相机运动与角色路径，保留地标/方向/目标/接触。
- **JU03 各层属于同一镜头**：核对透视/轮廓/线条/明暗/纹理/接地/遮挡/更新节奏。原速看2D/3D是否协调；特效怀疑遮主体时做开关对照。
- **JU04 用关键动作和声音检查力度**：写清起因—路径—重心—接触—反应—后果；动作声列预备/运动/接触/余响。特效支持主体与因果，不遮盖。

### 18.5 长篇情感编剧（30分钟）核心

- 主要人物分开写：外在目标 / 内在需要 / 错误判断 / 害怕失去 / 关系与资源。
- 重要转折来自**有代价的选择**，后果进入后续行动；主角有主动性，亲人和对手也有合理目标。
- 先建立共同经历，再试探→误解→带代价行动→新相处方式。多年伤害不能靠一句道歉消除。
- 情绪优先落到动作/潜台词/停顿，不能只靠旁白解释。
- 建立伏笔表：首次出现—观众当时理解—后续变化—回收—对选择的作用。
- 30分钟=1800秒，逐场记录地点/时间/目标/阻力/行动/状态/对白/伏笔/时长，再拆镜头。
- **禁止**：用循环或极慢放填足缺失剧情后宣称完整角色动画。
- 测时分开记录：纯对白 / 句间停顿 / 独立动作 / 反应预算。

### 18.6 审片先写证据范围（不凭印象下结论）

| 实际获得并检查的材料 | 可下结论 | 待检查 |

### 19.3 本地4K超分路线（16GB VRAM的真相）

**H3模型原生输出上限：** 720p（其实源片很多是864×480）
**4K正确姿势：** 不是"用模型直接跑4K"，而是：
1. 本地渲染/已有成片（720p级）
2. ffmpeg Lanczos超分到3840×2160 + unsharp锐化
3. h264_mf/hevc_mf硬件编码输出

**1080p/4K超分命令模板：**
```
# 1080p
ffmpeg -i in.mp4 -vf "scale=1920:1080:flags=lanczos,unsharp=5:5:0.8" -c:v libopenh264 out.mp4
# 4K
ffmpeg -i in.mp4 -vf "scale=3840:2160:flags=lanczos,unsharp=7:5:0.9" -c:v libopenh264 -c:a libmp3lame out.mp4
```

**诚实说明：** Lanczos是软件超分，细节是"画出来的"不是"生成的"。真要AI级超分需Real-ESRGAN逐帧（27分钟=39000帧，5080上约需数小时）。Lanczos是快路径，Real-ESRGAN是精修路径。

## 21. 【Real-ESRGAN逐帧AI超分】真4K精修路径（2026-10-06实测）

> Lanczos超分只是"拉大"，细节不会增加。真要AI级4K清晰度，必须用Real-ESRGAN逐帧超分。

### 21.1 工具与模型

- 路径：`F:\upscale_work\realesrgan-ncnn-vulkan.exe`
- 动画专用模型：`realesr-animevideov3-x4`（首选）
- 其他模型：`realesrgan-x4plus-anime`、`realesrgan-x4plus`（写实）
- Vulkan后端，吃GPU显存，**不要和ComfyUI同时跑**

### 21.2 正确流程（视频→真4K）

```
1. 拆帧：ffmpeg -i in.mp4 -vf scale=1920:1080 frames_in/frame_%05d.png
2. 超分：realesrgan-ncnn-vulkan -i frames_in -o frames_out -n realesr-animevideov3-x4 -s 4 -f png
3. 重组装：ffmpeg -framerate 24 -i frames_out/frame_%05d.png -i audio.aac -c:v h264_mf -b:v 20M -c:a copy out_4k.mp4
```

### 21.3 实测速度与注意事项

- 5080上速度：约57帧/分钟（~0.85秒/帧），1080p输入→7680×4320输出
- 3:46视频=5424帧≈95分钟
- 27分钟视频=39000帧≈11小时（必须过夜跑）
- **进程可能中途崩**：Real-ESRGAN ncnn版长时间批量可能静默退出。必须监控输出帧数是否持续增长
- 超分后7680×4320太大，重组装时用`scale=3840:2160:flags=lanczos`缩到4K
- 音轨单独提取再加回（Real-ESRGAN只处理视频帧）

### 21.4 为什么先降到1080p再超分

- H3原生输出480p-720p，直接超分x4=1920×1080~2880×1620，不够4K
- 先拉到1080p再AI超分x4=3840×2160真4K，AI会重新生成细节而不是简单放大
- 这是16GB显存能做到的"真4K"唯一路径

### 21.5 SAR/DAR修复（常见bug）

超分后的视频可能SAR不对（画面拉伸变形）。重组装时加`setsar=1`：
```
ffmpeg -i frames_out/%05d.png -vf "scale=3840:2160,setsar=1" -c:v h264_mf out.mp4
```

### 21.6 批量任务管理

- Real-ESRGAN跑的时候不要开ComfyUI/Chrome硬件加速/Ollama
- 跑完检查帧数：`(Get-ChildItem frames_out -Filter *.png).Count` 应等于输入帧数
- 缺帧会导致重组装时画面跳切，必须补跑
